# RAG 基础与 KnowVault 的问答链路

检索增强生成（Retrieval-Augmented Generation，RAG）把外部知识检索与大语言模型生成组合在一起：系统先从文档库中找到与问题相关的片段，再把片段作为上下文交给模型生成回答。KnowVault 把这条流程编号为 KV-RAG-2026，作为后续检索与评估工作的统一参照。

单纯依赖模型参数有三类风险：训练数据有截止时间，专业资料可能根本没有进入训练集，模型还可能在不确定时编造看似合理的内容。RAG 通过每次提问时现查资料，把回答限制在可核对的证据范围内，从而降低幻觉概率，也让资料更新不再依赖重新训练。

一条完整的 RAG 链路包含五步：解析文档、切分切片、向量化、检索候选、生成回答。解析负责从 PDF、Word、Markdown 等格式中抽取纯文本；切片把长文档拆成适合检索的短文本；向量化把切片映射成稠密向量；检索按问题找出最相关的若干切片；生成阶段把切片、问题和系统提示词一起交给模型。

查询改写是检索前的可选步骤。查询改写会把一个自然语言问题扩展成最多两条替代表述，再与原问题一起参与召回。它适合口语化、缩写较多或术语不统一的问题，但每次改写都会增加一次模型调用，因此 KnowVault 默认关闭该功能，只在需要时按请求开启。

引用溯源是 RAG 区别于普通聊天的重要能力。回答里的方括号编号对应检索到的切片，例如 [1] 表示第一条资料片段。前端根据编号展示原文、文档标题和标题层级，用户可以逐条核对答案是否有据可查。没有引用支撑的断言应当被视为可疑内容。

RAG 也有明确边界。检索不到正确片段时，再强的生成模型也无法给出可靠答案；切片质量差、问题与资料措辞差异大、资料本身相互矛盾，都会拉低最终效果。工程上通常先优化召回，再优化重排和提示词，最后才考虑微调模型。

KnowVault 当前不做模型微调，也不做联网搜索。它只使用用户上传并完成处理的文档作为知识来源。问答范围可以是单个知识库，也可以是多个知识库或全部可访问知识库；引用会带上知识库名称，方便在多库场景中定位来源。
