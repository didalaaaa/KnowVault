# 文档切片策略

切片是把长文档拆成可独立检索的文本单元。切片太短会丢失上下文，模型拿到零散句子难以判断含义；切片太长会稀释向量，一条切片里混入多个主题，检索得分不再聚焦。KnowVault 以字符数近似 token，避免为中文引入额外的分词依赖。

默认切片容量是 1000 个字符，重叠是 120 个字符，对应配置编号 KV-CHUNK-1000 与 KV-OVERLAP-120。容量和重叠都可以按知识库覆盖；容量下限为 100 个字符，重叠不会超过容量的一半，防止相邻切片互相吞没。

切片器优先按段落组织内容。文档先按空行拆成段落，再在容量范围内尽量把相邻段落放进同一个切片。只有单个段落超过容量时才会继续切分，因此大多数切片仍然保持语义完整。

单个段落超过容量时按句子边界切开，句号、问号、感叹号、分号和换行都可以作为切点。这种硬切不叠加重叠，编号 KV-SENTENCE-CUT，原因是重叠后仍可能超出容量，宁可断开也不产生超长切片。切片正文末尾会去掉多余空白，但不改写原始措辞。

重叠让相邻切片共享一段上下文。当答案刚好落在切点附近时，前一条切片尾部与后一条切片开头都能提供线索，降低因为边界切断而漏召回的概率。重叠也不是越大越好：重叠会放大存储与向量化成本，还会让相邻切片内容高度相似，挤占检索结果的名额。

每个切片保留标题层级路径，例如「第三章 > 部署」。标题路径既参与关键词稀疏索引，也会展示在引用抽屉里，帮助用户理解片段在原文中的位置。标题本身不重复写入正文，避免同一段标题在多个切片中反复计分。

切片参数需要与评估配套。语料固定、切片参数固定，Recall 和 nDCG 的变化才能归因到检索策略本身。若调整容量或重叠，旧向量必须重新生成，否则新旧切片会混在同一个集合里，指标不再可比。

切片数量还影响检索延迟与重排成本。切片越细，候选越多，重排要打分的文本越多；切片越粗，单条切片越长，向量化与存储开销越高。选择容量时要在召回精度与成本之间取平衡。
