# 向量检索与相似度

向量检索把文本映射为稠密向量，再在向量空间中寻找与问题最接近的切片。Embedding 模型负责把文本编码成一组浮点数，语义相近的文本在空间中距离更近。KnowVault 使用 BAAI/bge-m3 作为向量模型，固定输出 1024 维，对应编号 KV-VEC-1024。

向量维度必须与向量库配置一致。bge-m3 固定输出 1024 维，Qdrant collection 也按 1024 维创建；换用其他 embedding 模型时必须重新向量化全部文档，不能把不同维度的向量写进同一个字段。只更换重排模型则不需要重新向量化。

余弦相似度只比较两个向量的方向，不关心向量长度。它的取值范围是负一到一，越接近一表示方向越一致。文本向量通常已经归一化，因此余弦相似度与点积排序结果基本一致。相似度分数只适合在同一批候选内比较，不适合跨问题或跨模型直接对比。

Qdrant 使用 HNSW 图索引加速近似最近邻搜索。参数 HNSW-M32 表示每个节点保留 32 条边，边越多召回率通常越高，但内存和构建时间也会增加。KnowVault 使用默认索引参数，文档规模较小时近似搜索已经足够准确。

向量检索通常返回 top-k 条候选。top-k 太小会漏掉相关切片，太大则把噪声送进重排并增加成本。KnowVault 默认先宽召回约 20 条候选，再由重排模型精排，最终只保留 5 条作为引用。

所有知识库共用一个 Qdrant collection，通过 payload 过滤实现隔离。每条向量都带 tenantId、knowledgeBaseId、documentId 和 chunkIndex，检索时按知识库集合过滤。这样既避免为每个知识库单独维护 collection，也能在一次查询中覆盖多个知识库。

纯向量检索也有短板。它对精确编号、专有名词和罕见缩写不敏感：关键词完全一致的两段文本，向量未必排在最前；语义相近但包含错误数字的切片，向量反而可能得分很高。因此工程上常把向量检索与关键词检索组合成混合检索。

评估向量检索时，固定 embedding 模型、维度和距离度量，记录模型名称与日期。模型升级会改变整个向量空间，历史指标不能直接横向比较。
