## 1. 数据模型：五个迁移

### 1.1 迁移清单

| 迁移 | 表 | 变更 | 服务于 |
|---|---|---|---|
| `20261024025807_P4_ConversationContext` | `AppConversations` | 新增 `KnowledgeBaseId`、`LastMessageAt` | T2 / T10 |
| `20261024032758_P4_DocumentChunkHeading` | `AppDocumentChunks` | 新增 `HeadingPath`（512） | T3 / T4 |
| `20261024050306_P4_MessageFeedback` | `AppMessageFeedbacks` | 新表 + 唯一索引 | T6 |
| `20261024060725_P4_KnowledgeBaseSettings` | `AppKnowledgeBases` | 新增 4 个可空设置列 | T7 |

迁移不是一次性生成的，按任务顺序拆成五个；应用仍走 `dotnet run --project src/KnowVault.DbMigrator`

### 1.2 为什么新列一律可空

D12 明确「存量数据不回填」：旧文档没有 `HeadingPath`、旧消息没有 `LatencyMs`、旧知识库没有库级设置。所以 P4 新增列全部可空，老数据不需要迁移脚本，前端也必须把新字段当可选

读代码时形成条件反射：**看到 P4 新字段，先问它为空时业务走哪条分支**

| 字段为空 | 实际行为 |
|---|---|
| `Conversation.KnowledgeBaseId` | 按库过滤时不会出现在该库下；不过滤时照常显示，消息仍可读 |
| `Conversation.LastMessageAt` | 排序回落 `CreationTime` |
| `Message.LatencyMs` | 前端不显示耗时，仪表盘不把它算进平均值 |
| `DocumentChunk.HeadingPath` | 引用/详情只显示文档标题，不显示标题路径 |
| `KnowledgeBase.ChunkSizeChars` 等 | 摄入回落 `IngestOptions`，问答回落 `AiOptions` 或内置提示词 |
| `ChatMessageDto.Feedback` | 未评价，不是「点赞」 |

### 1.3 反馈表为什么必须唯一索引

`MessageFeedbackConfiguration` 里：

```csharp
// 同一用户对同一消息只允许一条反馈，切换赞/踩走更新而不是新增
builder.HasIndex(x => new { x.MessageId, x.UserId }).IsUnique();
// 会话删除与消息历史回填都按消息 ID 批量取
builder.HasIndex(x => x.MessageId);
```

业务含义是「一个用户对一条消息最多一条反馈」：切换赞/踩走更新，取消走删除。应用层虽然先 `FindAsync` 再写，但并发下仍可能同时插入两条；唯一索引是最后一道防线。代价是并发取消/切换时可能抛 `DbUpdateException`，当前作品规模接受这个取舍

### 1.4 `CitationsJson` 为什么放宽成 `text`

P4 之前引用只存 `documentId / title / chunkIndex / score`，`varchar(4000)` 够用。P4 增加 `Snippet`（前 300 字）和 `HeadingPath` 后，topK 条引用可能远超 4000 字符，继续限长会让「回答已经生成、落库却失败」

`MessageConfiguration.cs` 里因此不设上限，并保留注释说明原因。读消息时 `ParseCitations` 对坏 JSON 返回空列表，保证历史消息仍能打开

### 1.5 `HeadingPath` 的两份存储

同一份标题路径会写两处：

- PostgreSQL `AppDocumentChunks.HeadingPath`：文档详情抽屉按切片展示
- Qdrant payload `headingPath`：检索命中后直接组装引用，不用回表

`DocumentProcessor` 在构造 `VectorPoint` 和 `DocumentChunk` 时同时传入 `chunk.HeadingPath`。改动切片元数据时两处必须同步，否则会出现「详情有标题、引用没有」或反过来

## 2. 问答增量：`QaStreamService`

> 两段 UoW、Started/Delta/Completed 骨架、中途停止的「半截回答不入库」都在 P2 §2 阶段 4–5；这里只列 P4 改了什么

### 2.1 六处改动

| 改动 | 位置 | 为什么 |
|---|---|---|
| 沿用会话时校验归属、新会话记录知识库 | `ResolveConversationAsync` | 会话是个人工作区；会话也要能按库过滤 |
| 重新生成必须带会话 ID | `AskStreamAsync` 开头 | 没有会话就找不到「上一轮问题」 |
| 读取知识库设置 | 第一段 UoW 内 `FindAsync` | 库级 TopK / 系统提示词要参与本轮问答 |
| 重新生成不插入用户消息 | `if (!input.Regenerate)` | 复用同一编排，不新增 Hub 方法（D7） |
| 引用带片段与标题路径 | 构造 `RagCitationDto` | 首屏展示原文摘要，不用再请求 |
| 助手消息写耗时、刷新会话活动时间 | 第二段 UoW | 仪表盘平均值与会话列表排序的数据来源 |

入口的 Viewer ACL 校验在 P3 已有，P4 沿用；不要把它当成新逻辑

### 2.2 重新生成：不重复插入用户消息

服务端只做两件事：`Regenerate=true` 时不插入用户消息；读历史时把最后一轮用户提问及其后的助手回答一起剔除

```csharp
var ordered = messages.OrderBy(message => message.CreationTime).ToList();
if (excludeLastTurn)
{
    // 旧回答也要一起剔除：只删提问会让模型把上一版回答当成已经给出的上下文
    var lastUserIndex = ordered.FindLastIndex(message => message.Role == MessageRoleEnum.User);
    if (lastUserIndex >= 0) ordered.RemoveRange(lastUserIndex, ordered.Count - lastUserIndex);
}
```

注意是 `RemoveRange(lastUserIndex, ...)`，**旧回答也一起删**。只删提问会让模型把上一版回答当成已经给出的上下文，导致回答漂移

前端对应逻辑在 `chat.regenerate`：移除最后一条助手气泡，带同一条问题、`regenerate=true` 重发；`Started` 帧的 `UserMessageId` 此时为空，不能拿它去定位用户气泡

### 2.3 参数优先级：请求 > 库设置 > 全局

```csharp
var streamResult = await _ragService.AnswerStreamAsync(new RagRequest
{
    KnowledgeBaseId = knowledgeBaseId,
    TenantId = CurrentTenant.Id ?? Guid.Empty,
    ConversationId = conversation.Id,
    Question = input.Question,
    // 请求参数优先，其次知识库设置，最后交给全局配置
    TopK = input.TopK ?? knowledgeBase?.TopK ?? 0,
    SystemPromptOverride = knowledgeBase?.SystemPrompt,
    History = history
}, cancellationToken);
```

- `TopK` 传 `null`：本层不指定，继续看知识库设置，库也没设才回落 `AiOptions.TopK`
- `TopK` 传 `0`：显式跳过知识库设置（`0` 不是 `null`），直接让 `RagService` 回落全局 `AiOptions.TopK`
- 两条路径最后都会 clamp 到 1–8
- `SystemPromptOverride` 非空时，`RagPromptBuilder` **整体替换**内置系统提示词；空则用内置模板
- 检索范围看**本次请求**的 `knowledgeBaseId`；`Conversation.KnowledgeBaseId` 只决定会话列表归属，不强制检索范围。切换「提问范围」后继续同一会话，回答会来自新库，但会话仍归创建时的库

这一层没有改检索算法：宽召回、重排、失败降级仍是 P2 的 `RagService`

### 2.4 引用裁剪：300 字 + 标题路径

```csharp
var citations = streamResult.Chunks.Select(chunk => new RagCitationDto
{
    DocumentId = chunk.DocumentId,
    Title = chunk.DocumentTitle,
    ChunkIndex = chunk.ChunkIndex,
    Score = chunk.Score,
    Snippet = chunk.Content.Length <= CitationSnippetLength
        ? chunk.Content
        : chunk.Content[..CitationSnippetLength],
    HeadingPath = string.IsNullOrWhiteSpace(chunk.HeadingPath) ? null : chunk.HeadingPath
}).ToList();
```

为什么不在前端裁剪：首帧 `Started` 就要带回引用，每条都带完整切片会让消息体积不可控。完整原文在用户点击引用时再通过 `GetChunksAsync` 按 `chunkIndex` 取

`HeadingPath` 在这里做了一次空值归一化，保证前端拿到的是 `null` 或非空字符串，不用区分空串

### 2.5 帧契约扩展

`QaStreamEventDto` 在 P4 多了三个字段（`ConversationId` 在 P3 已有）：

| 帧 | 新字段 | 用途 |
|---|---|---|
| `Started` | `UserMessageId` | 前端把本地用户气泡补上真实 ID；重新生成时为空 |
| `Completed` | `AssistantMessageId` | 反馈、复制、重新生成需要稳定消息 ID |
| `Completed` | `LatencyMs` | 前端显示耗时，仪表盘后续统计 |

前端 `chat.js` 的映射：

```js
if (event.kind === EVENT_STARTED) {
  this.conversationId = event.conversationId
  assistant.citations = event.citations || []
  // 首帧带回本轮用户消息 ID；重新生成时为空
  if (event.userMessageId) {
    const user = [...this.messages].reverse().find((m) => m.role === 'user')
    if (user) user.id = event.userMessageId
  }
}
if (event.kind === EVENT_COMPLETED) {
  assistant.id = event.assistantMessageId || null
  assistant.latencyMs = event.latencyMs ?? null
}
```

**如果 `Started` 里没有用户消息 ID**，反馈仍能靠助手 ID 工作，重新生成也不依赖它；但用户气泡无法定位到真实消息。P4 把它作为契约的一部分，不要随意删

### 2.6 会话活动时间

第二段 UoW 里多了：

```csharp
conversation.Touch(_clock.Now);
await _conversationRepository.UpdateAsync(conversation, autoSave: true, cancellationToken);
```

它让会话列表按「最近活动」排序。中途停止或生成失败时不会走到第二段 UoW，所以 `LastMessageAt` 不更新，列表顺序保持原样——这是预期行为

## 3. 文档与知识库增量

> 上传、摄入、删除、重处理的主流程见 P1 §2 阶段 3 与 P3「按主题找代码」；下面只讲 P4 新增的读取与设置

### 3.1 切片接口 `GetChunksAsync`

```csharp
var document = await _documentRepository.GetAsync(id, cancellationToken: cancellationToken);
await _accessChecker.EnsureAsync(document.KnowledgeBaseId, KnowledgeBaseRoleEnum.Viewer, cancellationToken);

var chunks = await _chunkRepository.GetListAsync(x => x.DocumentId == id, cancellationToken: cancellationToken);
return chunks
    .OrderBy(c => c.ChunkIndex)
    .Select(c => new DocumentChunkDto { ... })
    .ToList();
```

要点：

- 先查文档再校验 Viewer，权限基于文档所属知识库
- 按 `ChunkIndex` 升序，前端直接用下标定位
- `HeadingPath` 对历史切片为空，UI 必须按可选处理

引用抽屉和文档详情抽屉共用这个接口：引用只带 300 字摘要，点击后拉完整切片；详情则一次展示全部切片

### 3.2 原件预览：`GetContentAsync` + 显式控制器

`DocumentAppService.GetContentAsync` 返回 `DocumentContentDto`，里面是 `Stream`，**ABP 动态 API 无法序列化**，所以方法标了 `[RemoteService(IsEnabled = false)]`，由 `DocumentContentController` 输出文件流：

```csharp
return download
    ? File(content.Stream, content.ContentType, content.FileName, enableRangeProcessing: true)
    : File(content.Stream, content.ContentType, enableRangeProcessing: true);
```

- `enableRangeProcessing: true` 让 PDF 预览可以分段加载
- 文件接口不走 ABP 的对象结果异常过滤，必须自己把 `AbpAuthorizationException`、`EntityNotFoundException`、`UserFriendlyException` 映射成 403/404/403
- 文件名优先 `SourceFileName`，没有则用 `Title + 扩展名`；MIME 由扩展名映射，未知类型走二进制流

前端（D4）用 axios 取 blob，而不是把接口地址直接塞进 iframe——iframe 直链带不上 Bearer：

| 类型 | 预览方式 |
|---|---|
| PDF | `URL.createObjectURL(blob)` 交给 iframe |
| HTML | 同上，但 iframe 必须保留空 `sandbox=""` |
| Markdown | `blob.text()` 直接展示 |
| Word / Excel | 浏览器不能内嵌渲染，点击预览直接下载 |

两个安全/资源点：

- **HTML 的 iframe 必须保留空 `sandbox=""`**，禁止上传文件执行脚本
- **PDF 不能加 sandbox**，否则浏览器内置阅读器白屏
- object URL 在关闭预览或组件卸载时 `revokeObjectURL`，避免 blob 长期占内存

### 3.3 知识库设置 `UpdateSettingsAsync`

```csharp
await _accessChecker.EnsureAsync(input.Id, KnowledgeBaseRoleEnum.Owner, cancellationToken);

var knowledgeBase = await _knowledgeBaseRepository.GetAsync(input.Id, cancellationToken: cancellationToken);
ValidateSettings(input, knowledgeBase);

knowledgeBase.UpdateSettings(
    input.ChunkSizeChars,
    input.ChunkOverlapChars,
    input.TopK,
    Normalize(input.SystemPrompt));
```

校验范围（`ValidateSettings`）：

- 切片长度 200–4000
- 重叠 0–`min(500, 生效长度 / 2)`
- TopK 1–8
- 系统提示词最长 4000（DTO 上的 `[StringLength]`）

重叠上限依赖「生效后的切片长度」，所以要把知识库现有值一起算进来：

```csharp
var effectiveSize = chunkSize ?? knowledgeBase.ChunkSizeChars ?? DefaultChunkSizeChars;
var maxOverlap = Math.Min(500, effectiveSize / 2);
```

生效范围：

- `ChunkSizeChars` / `ChunkOverlapChars`：只在 `DocumentProcessor` 摄入时读取，**只影响新文档**
- `TopK` / `SystemPrompt`：只在 `QaStreamService` 提问时读取，**只影响新提问**
- 已生成的切片不会因为改设置而重算；要让旧文档生效，只能重新处理

读代码时注意：默认知识库对所有登录用户返回 `Editor`，而设置接口要求 `Owner`。非管理员在默认库上保存设置会被拒绝，前端设置按钮并未按角色禁用——演示库设置时用自建知识库或管理员账号

### 3.4 批量上传：只改前端

D5 明确后端保持单文件接口：

- `n-upload` 开 `multiple`
- 每个文件走 `custom-request`，逐个调用 `store.upload`
- `uploadingCount` 逐条计数，归零才解除按钮 loading
- 每个文件完成后 `scheduleRefresh`，300ms 防抖合并成一次列表请求
- 有 Pending/Processing 文档时每 2 秒轮询，全部完成自动停止

```js
async upload(file) {
  this.uploadingCount += 1
  try {
    await documentApi.upload({ knowledgeBaseId: this.knowledgeBaseId, file })
    this.scheduleRefresh()
    return { ok: true }
  } catch (e) {
    return { ok: false, message: ... }
  } finally {
    this.uploadingCount -= 1
  }
}
```

为什么不做批量后端接口：现有单文件接口已经包含权限、去重、对象存储、消息发布，批量接口只会多一层 stream 集合契约，收益低、风险高。前端并发上传时，同库文件名去重仍由后端逐条兜底

### 3.5 工作台整合（T10）

T10 把原来的「知识库」和「资料」两个页面合并成一个 `KnowledgeWorkspace`：

- 左栏：知识库列表（名称、默认标记、描述、已就绪数）
- 右栏：当前库标题、统计、设置/成员/编辑/删除 + `KnowledgeDocuments`
- 问答页：侧栏只留会话，聊天头部新增「提问范围」选择器

**唯一选中状态**：`documents.knowledgeBaseId`。工作台切换、聊天范围选择、会话侧栏刷新都读这一份，不允许再引入第二份 `selectedKbId`。这是 T10 最重要的架构约束

默认知识库：

- 不可删除
- 不可改成员（成员按钮禁用）
- 所有登录用户等价 Editor

`KnowledgeWorkspace.vue` 里用常量 `defaultKnowledgeBaseId` 与后端 `KnowVaultConsts.DefaultKnowledgeBaseId` 保持一致；改 ID 时两边必须同步

## 4. 会话、反馈与账户

### 4.1 会话归属：所有入口统一校验

`ConversationAppService` 的读、改名、删除都先走：

```csharp
private async Task<Conversation> GetOwnedConversationAsync(Guid id, CancellationToken cancellationToken)
{
    var conversation = await _conversationRepository.GetAsync(id, cancellationToken: cancellationToken);
    if (conversation.CreatorId != CurrentUser.Id)
    {
        throw new AbpAuthorizationException("无权访问该会话");
    }
    return conversation;
}
```

会话是个人工作区，管理员也不查看他人会话（D2）。新增入口时不要绕过这个方法；问答入口 `QaStreamService.ResolveConversationAsync` 也有一份同样的 `CreatorId` 校验，两处都要保留

列表查询直接按 `CreatorId` 过滤，并支持可选 `knowledgeBaseId`：

```csharp
x => x.CreatorId == userId && (knowledgeBaseId == null || x.KnowledgeBaseId == knowledgeBaseId)
```

消息按 `CreationTime` 升序；会话列表按 `LastMessageAt ?? CreationTime` 降序。作品规模下在内存排序，P5 再下推 SQL

删除会话要级联：先找出消息 ID，再删这些消息上的反馈，再删消息，最后删会话。顺序不能反，否则会留下孤儿反馈

### 4.2 反馈：三态与唯一性

`FeedbackAppService.SetAsync`：

- 只允许评价助手消息
- 只允许评价自己会话里的消息
- `(MessageId, UserId)` 先查后写
- `Rating == null` 删除已有反馈
- 否则插入或更新

前端 `chat.feedback` 做乐观更新：

```js
const previous = message.feedback
const next = previous === rating ? null : rating
message.feedback = next

try {
  const saved = await feedbackApi.set({ messageId: message.id, rating: next })
  message.feedback = saved ?? null
} catch (e) {
  message.feedback = previous
  throw e
}
```

再次点击同一评分表示取消；请求失败回滚

### 4.3 一个真实 bug：未评价为什么显示成点赞

`GetMessagesAsync` 最初这样写：

```csharp
var feedbackByMessage = feedbacks.ToDictionary(x => x.MessageId, x => x.Rating);
// ...
Feedback = feedbackByMessage.GetValueOrDefault(x.Id)
```

`FeedbackRatingEnum` 是值类型，`GetValueOrDefault` 对缺失键返回 `default(FeedbackRatingEnum)`，也就是 `Like(0)`。结果所有未评价消息都显示成已点赞

修复方式是显式提升为可空：

```csharp
// 值类型字典的默认值是 Like(0)，缺反馈时会误显示为已点赞，显式提升为可空
var feedbackByMessage = feedbacks.ToDictionary(x => x.MessageId, x => (FeedbackRatingEnum?)x.Rating);
```

这样缺失键返回 `null`，前端三态才正确。**改这段代码时不要退回值类型字典**

### 4.4 账户：Identity 失败统一翻译

`AccountAppService` 的注册流程：

1. `[AllowAnonymous]`
2. 用户名、邮箱规范化后查重
3. 创建 `IdentityUser`，`Name` 存显示名
4. 加入 `Member` 角色
5. 返回资料 DTO

改资料：

- 显示名为空白时回落用户名
- 邮箱变更前检查是否被其他账号占用
- 邮箱没变时走 `UpdateAsync`，变了走 `SetEmailAsync`

改密码：

- `IdentityUserManager.ChangePasswordAsync`
- 成功后当前令牌仍有效，下次登录用新密码

Identity 的失败有两种形态：返回 `IdentityResult` 失败，或直接抛 `AbpIdentityResultException`。`ExecuteAsync` 把后者还原成 `IdentityResult`，再统一走 `EnsureSucceeded` 和 `TranslateError`，保证前端拿到的都是中文文案

### 4.5 退出登录要清 XSRF

`auth.logout` 除了清 token 与 profile，还多了一行：

```js
// 防伪令牌绑定了当前用户声明，退出后不清掉会让匿名的注册请求被 400 拒绝
document.cookie = 'XSRF-TOKEN=; Max-Age=0; path=/'
```

ABP 的防伪 cookie 绑定当前用户声明。不清掉的话，退出后打开注册页提交会被 400 拒绝；这是 P4 加注册入口后才暴露的接缝

## 5. 前端增量

### 5.1 Store 关系

```text
auth
  token / profile / displayName
  login / logout / loadProfile
conversations             ← P4 新增
  items / loading / error
  refresh / rename / remove / reset
documents
  knowledgeBases / knowledgeBaseId / documents / uploadingCount
  refresh / upload / scheduleRefresh / updateKnowledgeBaseSettings
chat
  conversationId / messages
  ask / regenerate / feedback / copy / stop / loadConversation
```

P4 的 Store 约束：

- `documents.knowledgeBaseId` 是**唯一**的知识库选中状态，工作台和问答页共用
- `conversations.items` 只存摘要，消息按需通过 `chat.loadConversation` 拉取
- 流订阅句柄 `subscription`、防抖与轮询定时器都放模块级，不塞进 Pinia state（不可序列化，也没必要响应式）

### 5.2 `ChatPanel`

P4 在聊天头部加了「提问范围」选择器，直接绑定 `documents.knowledgeBaseId`；发送与重新生成都把它传给 `chat`：

```js
await chat.ask(q, documents.knowledgeBaseId)
await chat.regenerate(documents.knowledgeBaseId)
```

发送/重新生成后会刷新会话侧栏，让新会话或最近活动时间及时反映到列表

助手回答用 `markdown-it` 渲染（`html: false`，D10），用户消息保持纯文本；操作条含点赞/点踩、复制、重新生成、耗时

### 5.3 两个抽屉

`CitationDrawer`：

- 打开时按 `documentId + chunkIndex` 拉切片，命中后显示完整正文
- 拉取失败或未找到切片时，退回引用自带的 300 字 `Snippet`
- 标题路径优先用切片里的，回落到引用自身字段（兼容旧会话）
- 「查看文档」把引用交给父组件，打开 `DocumentDetailDrawer`

`DocumentDetailDrawer`：

- 上半部分是切片列表，按 `ChunkIndex` 展示，`HeadingPath` 可选
- 下半部分是原件预览/下载，按 §3.2 的类型分流
- 关闭预览和组件卸载时释放 object URL

### 5.4 `KnowledgeWorkspace` 与 `KnowledgeDocuments`

- 工作台左栏切换知识库只改 `documents.knowledgeBaseId`，右栏文档列表自动跟随
- 设置弹窗把空值统一转成 `null` 再提交，表示「回落全局」
- 文档上传组件是多选 + `custom-request`，每个文件独立成败，局部失败不打断其余文件
- 删除文档时 `deletingId` 非空，界面显示全局遮罩并禁止其它操作

### 5.5 `DashboardPanel`

`DashboardAppService.GetAsync` 的统计口径：

- 文档：当前用户**可见知识库**下的文档（`GetAccessibleIdsAsync`）
- 会话：当前用户**本人**的会话
- 提问数：这些会话里的用户消息
- 平均耗时：最近 7 天、有 `LatencyMs` 的助手消息
- 趋势：最近 7 个自然日，按服务器本地日期切分

作品规模下都是取列表后内存聚合，P5 再下推 SQL

前端图表生命周期：

- `echarts.init` 在数据回来并 `nextTick` 后执行
- 刷新时复用同一个实例 `setOption(..., true)`
- `resize` 监听在 `onBeforeUnmount` 移除，图表 `dispose`，避免切页后内存泄漏

`ProfileModal` 只做两件事：保存资料、修改密码。改密成功后当前登录保持有效，下次登录用新密码——前端不强制退出
