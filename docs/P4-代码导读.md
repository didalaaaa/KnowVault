# P4 代码导读

> P4 的目标是把 KnowVault 从「能跑通 RAG」打磨成「可以完整演示的作品」：账户、会话、引用原文、文档预览、批量上传、反馈与重生成、库设置、仪表盘，以及把资料库并入知识库的工作台。
> 规格与验收记录见 `docs/plans/2026-10-24-knowvault-p4-mvp.md`；实现细节定稿见 `TECH_STACK.md` §9.6。

## 2. 按主题索引

### 2.1 后端：问答、引用与重生成

| 文件 | 职责 | 备注 |
|---|---|---|
| `src/KnowVault.Application/Qa/QaStreamService.cs` | 流式问答主编排：会话解析、历史加载、RAG 调用、引用裁剪、消息落库 | 不依赖环境 UoW；落库显式 `Begin(requiresNew: true)` |
| `src/KnowVault.Application/Qa/QaAppService.cs` | REST 问答入口，把同一条流拼成整段文本 | 与 SignalR 共用编排 |
| `src/KnowVault.Application.Contracts/Interfaces/IQaStreamService.cs` | Hub 与应用层之间的流式契约 | `Started / Delta / Completed` 三帧 |
| `src/KnowVault.Application.Contracts/Models/Qa/QaStreamEventDto.cs` | 流事件模型 | `Started` 帧带 `ConversationId` 与引用 |
| `src/KnowVault.Application.Contracts/Models/Qa/RagCitationDto.cs` | 引用契约 | P4 增加 `Snippet`、`HeadingPath` |
| `src/KnowVault.Ai/Rag/RagService.cs` | 检索 → 重排 → Prompt → 生成 | 重排失败 fail-open，退回向量顺序 |
| `src/KnowVault.Ai/Rag/RagPromptBuilder.cs` | 系统提示词与历史拼装 | 支持知识库级系统提示词覆盖 |

**关键不变量**

- **重新生成不重复插入用户消息**：`Regenerate=true` 时只重新回答上一轮问题，历史加载会排除最后一条用户消息；前端先移除最后一条助手气泡再请求。
- **引用裁剪在应用层完成**：`QaStreamService` 把 `RagRequest` 的结果转成 `RagCitationDto`，`Snippet` 超长时截断，`HeadingPath` 为空归 null。
- **流式落库要独立 UoW**：枚举期间环境 UoW 已结束，所有写库必须自己开工作单元。

### 2.2 后端：文档生命周期

| 文件 | 职责 | 备注 |
|---|---|---|
| `src/KnowVault.Application/Documents/DocumentAppService.cs` | 上传、列表、切片、原件、删除、重处理 | 上传入口被 `[RemoteService(IsEnabled = false)]` 移出动态 API，由显式控制器暴露 |
| `src/KnowVault.HttpApi/Controllers/DocumentUploadController.cs` | `POST /api/app/document/upload` | multipart 必须显式 `[FromForm]` |
| `src/KnowVault.Application.Contracts/Models/Documents/DocumentChunkDto.cs` | 切片展示模型 | 带上 `HeadingPath` 供详情抽屉分组 |
| `src/KnowVault.Domain/Models/Documents/Document.cs` | 文档聚合 | `SourceFileName` 支持同库文件名去重 |
| `src/KnowVault.Domain/Models/Documents/DocumentChunk.cs` | 切片实体 | P4 增加 `HeadingPath` |
| `src/KnowVault.Ingest/Processing/DocumentProcessor.cs` | 解析 → 切片 → 向量化 → 标记状态 | 切片参数优先取所属知识库设置 |
| `src/KnowVault.Ingest/Messaging/DocumentIngestConsumer.cs` | RabbitMQ 消费与重试 | 令牌取 `context.CancellationToken` |

**关键不变量**

- **设置只影响新文档**：`ChunkSizeChars` / `ChunkOverlapChars` 在摄入时读取，已生成的切片不重算；前端设置弹窗必须提示。
- **删除顺序**：Qdrant points → 切片 → 文档 → MinIO 原文件；MinIO 删除失败只记 warning，不阻塞数据库清理。
- **重复上传拒绝**：同一知识库内按原始文件名（忽略大小写）拒绝；存量文档 `SourceFileName` 为空不回填。

### 2.3 后端：会话、反馈与账户

| 文件 | 职责 | 备注 |
|---|---|---|
| `src/KnowVault.Application/Chat/ConversationAppService.cs` | 会话列表、消息列表、重命名、删除 | 所有入口走 `GetOwnedConversationAsync` |
| `src/KnowVault.Application/Chat/FeedbackAppService.cs` | 点赞/点踩 | `(MessageId, UserId)` 唯一，同评分再次提交视为取消 |
| `src/KnowVault.Domain/Models/Chat/Conversation.cs` | 会话聚合 | `KnowledgeBaseId`、`LastMessageAt` |
| `src/KnowVault.Domain/Models/Chat/Message.cs` | 消息聚合 | `CitationsJson` 为 `text`，`LatencyMs` 记录耗时 |
| `src/KnowVault.Domain/Models/Chat/MessageFeedback.cs` | 反馈实体 | 评分枚举 `FeedbackRatingEnum` |
| `src/KnowVault.Application/Account/AccountAppService.cs` | 注册、资料、改密 | 注册默认加入 `Member`；改密后当前令牌仍有效 |

**关键不变量与坑**

- **反馈映射必须可空**：`Dictionary<Guid, FeedbackRatingEnum>.GetValueOrDefault` 对缺失键返回 `Like(0)`，会让未评价消息误显示为已点赞；P4 验收期改为 `Dictionary<Guid, FeedbackRatingEnum?>`。改动这段代码时不要退回值类型字典。
- **归属校验统一**：会话的读、写、删除、反馈都必须确认当前用户是会话创建者；不要新增绕过 `GetOwnedConversationAsync` 的入口。
- **反馈只回填自己的**：`GetMessagesAsync` 只查当前用户对这批消息的反馈，别人的评价不暴露。

### 2.4 后端：知识库、成员与仪表盘

| 文件 | 职责 | 备注 |
|---|---|---|
| `src/KnowVault.Application/KnowledgeBases/KnowledgeBaseAppService.cs` | 增删改查、设置 | 删除仅限空库；默认库不可删 |
| `src/KnowVault.Application/KnowledgeBases/KnowledgeBaseAccessChecker.cs` | 统一权限判定 | Admin 短路；默认库等价 Editor；其余查成员表 |
| `src/KnowVault.Application/KnowledgeBases/KnowledgeBaseMemberAppService.cs` | 成员列表/设置/移除 | 仅 Owner；默认库拒绝；不能移除最后一个 Owner |
| `src/KnowVault.Application.Contracts/Models/KnowledgeBases/KnowledgeBaseSettingsInput.cs` | 设置契约 | 长度 200–4000、重叠 0–min(500, 长度/2)、TopK 1–8 |
| `src/KnowVault.Application/Dashboard/DashboardAppService.cs` | 概览统计 | 按当前用户与其可访问知识库聚合 |

**关键不变量**

- **默认知识库对所有登录用户等价 Editor**，但成员管理接口对它直接返回空/拒绝。
- **权限缓存**：改角色或成员后，旧令牌的权限缓存可能仍生效；验收 403 需要重新登录或等待缓存过期。
- **趋势口径是提问数**：`Last7DayQuestions` 统计 `Role=User` 的消息，不是助手回答数；无数据日期补 0。

### 2.5 前端：应用壳与状态

| 文件 | 职责 | 备注 |
|---|---|---|
| `frontend/src/App.vue` | 三个主页面（概览/问答/知识库）、登录切换、全局弹窗 | 问答页 = 会话侧栏 + ChatPanel；知识库页 = KnowledgeWorkspace |
| `frontend/src/stores/auth.js` | 登录、登出、当前用户、资料同步 | 令牌存 `localStorage` 的 `knowvault.token` |
| `frontend/src/stores/documents.js` | 知识库列表、当前库、文档列表、上传/删除/轮询 | `knowledgeBaseId` 是工作台与问答页共享的当前库 |
| `frontend/src/stores/conversations.js` | 会话列表、重命名、删除 | 监听 `documents.knowledgeBaseId` 后刷新 |
| `frontend/src/stores/chat.js` | 消息、流式连接、反馈、重生成、复制 | 反馈用 `null` 表示未评价 |
| `frontend/src/api/http.js` | axios 实例、令牌、XSRF、401 处理 | 所有 API 统一走这里 |
| `frontend/src/api/qaHub.js` | SignalR 连接与流消费 | 令牌走 query string，Host 中间件搬运为 Bearer |

**关键不变量**

- **当前知识库只有一个来源**：`documents.knowledgeBaseId`。工作台选择、聊天头部「提问范围」、会话侧栏刷新都围绕它，不要再引入第二份选中状态。
- **反馈状态三态**：`null` 未评价、`0` 有帮助、`1` 没帮助；模板用 `=== 0` / `=== 1` 判断高亮。
- **流式状态与 loading 分离**：`chat.streaming` 控制「停止生成」，`chat.loading` 控制输入禁用与发送按钮 loading。

| `frontend/src/components/RegisterPanel.vue` / `LoginPanel.vue` | 注册/登录切换 | 注册成功回登录并预填用户名 |
| `frontend/src/utils/markdown.js` | `markdown-it` 实例 | **`html:false` 是安全开关，不要打开** |

**安全与体验约束**

- 助手回答用 `renderMarkdown` + `v-html`；用户消息保持纯文本。
- HTML 原件预览的 `iframe` 必须保留空 `sandbox`，防止上传 HTML 执行脚本。
- 预览用的 object URL 在抽屉关闭或组件卸载时立即 `revokeObjectURL`。
- 交互焦点要可见；动效控制在 150–300ms，不做阻塞式动画。

## 3. 一次演示请求的完整链路

以「在验收知识库提问」为例：

1. `ChatPanel` 读取 `documents.knowledgeBaseId`，调用 `chat.ask(question, kbId)`。
2. `chat` store 通过 `qaHub` 发起 SignalR 流；服务端进入 `QaStreamService.AskStreamAsync`。
3. `KnowledgeBaseAccessChecker` 校验 Viewer 权限；解析或新建会话，加载历史（重生成时排除最后一条用户消息）。
4. `RagService` 用 SiliconFlow 向量化问题，Qdrant 按 `tenantId + knowledgeBaseId` 宽召回，再走 SiliconFlow 重排取 topK。
5. Prompt 组装后调用 DeepSeek 流式生成；`Started` 帧先把引用推给前端。
6. 每个 `Delta` 追加到气泡；`Completed` 后服务端写助手消息（含 `CitationsJson` 与 `LatencyMs`），前端刷新会话侧栏。
7. 点击引用：`CitationDrawer` 展示 `Snippet` 与 `HeadingPath`；「查看文档」打开 `DocumentDetailDrawer` 并加载切片与原件。
8. 点赞/点踩写入 `MessageFeedback`；刷新后 `GetMessagesAsync` 回填当前用户的评分。

## 4. 测试与验证

```bash
# 后端构建与测试（集成测试需要 Docker）
dotnet build KnowVault.slnx
dotnet test KnowVault.slnx --no-build

# 前端构建
cd frontend && npm run build
```

- 单测：`tests/KnowVault.Tests`（35 项）覆盖切片、解析、引用 payload、Prompt、重排解析与降级等纯函数行为。
- 集成测试：`tests/KnowVault.IntegrationTests`（3 项）覆盖上传→处理→删除的存储一致性、重处理不重复切片、同库文件名去重。
- 会话归属与重生成目前靠手工验收（P4 §2 第 8、9 项）；如需自动化，建议在集成测试中补「他人会话读写被拒」与「重生成不新增用户消息」两条。
- 手工验收：按 `docs/plans/2026-10-24-knowvault-p4-mvp.md` §2 的 15 项逐条走查；其中 Aspire 一键启动依赖本机 DCP 稳定性，失败时可使用等价的 `kv-*` 手工容器路径（见 `TECH_STACK.md` §7）。

## 5. 常见改动指引

| 想改什么 | 先看哪里 | 注意 |
|---|---|---|
| 调整回答风格 | `RagPromptBuilder`、知识库「系统提示词」设置 | 系统提示词覆盖只影响该库 |
| 调整切片策略 | `DocumentChunker`、`DocumentProcessor`、库设置 | 只影响新文档；改了默认值要同步单测与文档 |
| 增加引用字段 | `RagCitationDto`、`QaStreamService` 映射、`ChatMessageDto`、前端 `CitationDrawer` | 旧消息的 `CitationsJson` 可能缺字段，前端按可选处理 |
| 增加反馈维度 | `MessageFeedback`、`FeedbackAppService`、`ChatPanel` 操作条 | 迁移要可空或有默认值，避免历史数据报错 |
| 改仪表盘口径 | `DashboardAppService`、`DashboardPanel` | 必须保持「按当前用户 + 可访问库」的隔离 |
| 换前端视觉 | `frontend/src/styles/main.css`、各组件 scoped 样式 | 保持暖纸/墨绿基调与可见焦点，不引入第二套主题 |
