## 一、目标

### 1.1 定位

KnowVault 是一个可本地运行、可完整演示的多格式文档 RAG 知识库。作品的重点不是"能上线运营"，而是：

- **功能完整**：从注册、建库、导入、检索、问答到会话管理形成闭环
- **技术有深度**：混合检索、重排、流式、可观测、集成测试都有真实实现
- **可复现**：陌生人能按 README 在本地跑起来并走完全流程
- **可阅读**：架构图、设计取舍、评估报告、代码导读齐备

### 1.2 陌生人测试

在一台装有 Docker 与 .NET 10 的干净机器上，按 README 操作、不求助作者，完成以下十步：

1. 一条命令启动后端、前端与全部依赖
2. 注册账号并登录
3. 创建知识库，批量导入多个文档
4. 看到解析 → 切片 → 向量化的状态变化
5. 预览文档原文与切片列表
6. 提问并看到流式回答
7. 点击引用，看到原文片段并高亮
8. 刷新页面，找回历史会话并继续追问
9. 对回答点赞/点踩，重新生成一次
10. 在仪表盘看到文档数、问答量与耗时

十步全部通过，才认为达到"完整作品"。

### 1.3 完成定义（DoD）

- **功能**：P4、P5、P6 的验收清单逐项通过并留证
- **可运行**：`docker compose up` 一条命令完成 P4 全流程
- **可阅读**：README 含架构图、功能截图/GIF、快速开始、配置说明、设计取舍
- **可合规**：LICENSE 明确、仓库无真实密钥、依赖许可已核对

## 二、现状

### 2.1 已有能力

| 域 | 已实现 |
|---|---|
| 文档摄入 | PDF/Word/Excel/Markdown/HTML 解析、切片、SiliconFlow 向量化、RabbitMQ 异步处理、5×2s 重试、error queue |
| 检索问答 | Qdrant 向量检索、BGE 重排、DeepSeek 流式生成、多轮会话、引用元数据、停止生成 |
| 知识库 | 增删改查、成员管理、Admin/Member/Viewer + Owner/Editor/Viewer 双层权限、默认库 |
| 文档治理 | 删除（向量/切片/文件）、重新处理、同库文件名去重、状态轮询 |
| 工程 | ABP 分层、Aspire 本地编排、OTel + Seq、Testcontainers 四件套、单元测试 |
| 前端 | 登录、知识库、文档、聊天四个主界面，SignalR 流式渲染 |

### 2.2 关键缺口

| 模块 | 缺口 |
|---|---|
| 账户 | 无注册、无个人中心、无改密 |
| 会话 | 有 `Conversation` 实体，但无列表/重命名/删除 API，前端刷新即丢 |
| 引用 | 只有文档标题与 chunk 序号，打不开原文、看不到命中片段 |
| 文档 | 只能单文件上传；无原文预览、无 chunk 预览、无启停与标签 |
| 问答 | 无赞踩反馈、无重新生成、无复制/导出 |
| 知识库 | 切片与检索参数写死在配置里，不能按库设置 |
| 运营 | 无仪表盘、无任务中心、无用量统计 |
| 检索 | 纯向量召回，无关键词混合、无查询改写、无多库联合问答 |
| 评估 | 无金标集、无检索指标、无对比报告 |
| 交付 | 无 Docker Compose、无 README、无 LICENSE、无示例数据 |

## 三、范围决策

### 3.1 保留（作品完整度必需）

注册与个人中心、会话管理、引用原文、文档与切片预览、批量上传、赞踩与重新生成、知识库设置、轻量仪表盘、混合检索、查询改写、多库问答、评估报告、成本统计、Docker Compose、README 与截图。

### 3.2 可选加分（有余力再做）

| 能力 | 说明 |
|---|---|
| 模型供应商配置界面 | 把 appsettings 的模型配置搬到界面，含连通性测试 |
| URL 导入 | 输入网页地址抓取正文，复用现有 HTML 解析 |
| 语义缓存 | 相似问题命中缓存，降低响应时间与成本 |
| Gitee Go CI | 只跑 build + 单测；集成测试受额度限制不进 CI |
| 多租户演示分支 | 仅演示租户隔离，不并入主线 |

### 3.3 明确不做

| 能力 | 原因 |
|---|---|
| 多租户正式启用 | 个人作品无多租户场景；保留 `TenantId` 结构即可展示架构预留 |
| 用户管理后台 | 无运营需求 |
| 开放 API / API Key | 无外部调用方 |
| 限流、审计、备份恢复 | 不部署上线，无实际收益 |
| 外部数据源（飞书/Notion/Confluence） | 依赖第三方账号，访客无法复现 |
| OCR、移动端 App、K8s、模型微调、计费 | 与展示目标无关，投入产出低 |

## 四、阶段路线图

### P4 演示完整度

**目标**：陌生人能独立走完 1.2 的十步，界面不再有"半成品"感。

| 编号 | 任务 | 内容 | 依赖 |
|---|---|---|---|
| P4-T1 | 账户体验 | 注册页、个人中心（显示名、改密）；README 注明种子账号仅本地使用 | — |
| P4-T2 | 会话管理 | 会话列表/重命名/删除/按知识库过滤；消息历史加载；前端侧边栏切换 | — |
| P4-T3 | 引用溯源 | 引用增加原文片段与位置；按 chunk 查询上下文；前端抽屉展示并高亮命中句 | P4-T4 可并行 |
| P4-T4 | 文档详情 | 文档元数据、处理状态、原文预览/下载、切片列表 | — |
| P4-T5 | 批量上传 | 多选/拖拽、逐文件状态、失败原因展示 | — |
| P4-T6 | 问答闭环 | 赞踩反馈（落库）、重新生成、复制答案 | P4-T2 |
| P4-T7 | 知识库设置 | 切片大小/重叠、检索 topK/阈值、按库 Prompt 入库并生效 | — |
| P4-T8 | 轻量仪表盘 | 知识库数、文档数、问答数、平均响应耗时、失败任务数 | P4-T2/T4 |
| P4-T9 | 验收 | 按 1.2 十步走查，留存截图 | 全部 |

**验收标准**

- 新用户可自行注册并登录，种子账号也能用
- 关闭浏览器重开，历史会话可找回并继续追问
- 点击任一引用能看到对应原文切片，命中内容有高亮
- 可一次选择 3 个以上文件上传，逐个显示状态，失败可见原因
- 赞踩与重新生成可用，反馈数据可在数据库查到
- 修改某知识库的切片参数后，新上传文档按新参数切片
- 仪表盘数字与实际数据一致

### P5 检索含金量

> 状态：**进行中（2026-10-27）**。需求见 [`docs/driver/需求/需求分析-1027-P5.md`](../driver/需求/需求分析-1027-P5.md)，实施计划见 [`docs/plans/2026-10-27-knowvault-p5-mvp.md`](2026-10-27-knowvault-p5-mvp.md)。

**目标**：回答质量可度量、可对比、可解释，这是作品与"玩具 Demo"的分水岭。

| 编号 | 任务 | 内容 | 依赖 |
|---|---|---|---|
| P5-T0 | 混合检索选型 | 在 Qdrant sparse、PostgreSQL 全文/zhparser、OpenSearch 之间冻结方案并记录理由 | — |
| P5-T1 | 混合检索 | 关键词召回 + 向量召回，RRF 融合，权重与候选数可配置 | P5-T0 |
| P5-T2 | 查询改写 | LLM 多查询或 HyDE，可开关，限制额外调用成本 | P5-T1 |
| P5-T3 | 多库/全局问答 | 多知识库范围选择与过滤条件合并 | P5-T1 |
| P5-T4 | 评估体系 | 30 条金标集；Recall@K、MRR、nDCG、引用准确率；生成 Markdown 报告 | P5-T1 |
| P5-T5 | 成本统计 | 记录生成/向量化/重排的 token 与耗时，按库、按天聚合，接入仪表盘 | — |
| P5-T6 | 验收 | 纯向量 / 混合 / 混合+改写 三组对比报告；多库问答可用；成本可见 | 全部 |

**验收标准**

- 同一金标集上输出三组指标报告，混合检索相对纯向量有可解释的提升或明确的持平结论
- 报告进入仓库，README 可直接引用
- 多库问答可选择 2 个以上知识库并正确过滤
- 每次问答的 token 与耗时可在仪表盘按天查看
