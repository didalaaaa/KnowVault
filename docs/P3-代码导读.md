## 推荐阅读顺序（从零读懂 P3）

每一步只追一条请求，读完能回答右边的问题就算过关。

| 步骤 | 阅读顺序 | 读完应能回答 |
|---|---|---|
| 1. 上传入口 | [DocumentUploadController.cs](src/KnowVault.HttpApi/Controllers/DocumentUploadController.cs) → [DocumentAppService.cs](src/KnowVault.Application/Documents/DocumentAppService.cs) 的 `UploadAsync` → `IDocumentIngestPublisher` | 文件先落到哪、文档记录何时入库、消息为什么在提交后才发？ |
| 2. 摄入管线 | [DocumentIngestConsumer.cs](src/KnowVault.Ingest/Messaging/DocumentIngestConsumer.cs) → [DocumentProcessor.cs](src/KnowVault.Ingest/Processing/DocumentProcessor.cs) → 解析/切片/Embedding → Qdrant + `DocumentChunk` | 失败时 `Failed` 状态为什么不会被外层事务回滚？消息为什么会重投？ |
| 3. 问答链路 | [QaHub.cs](src/KnowVault.HttpApi/Hubs/QaHub.cs) / [QaAppService.cs](src/KnowVault.Application/Qa/QaAppService.cs) → [QaStreamService.cs](src/KnowVault.Application/Qa/QaStreamService.cs) → [RagService.cs](src/KnowVault.Ai/Rag/RagService.cs) → Embedding / Rerank / DeepSeek | 一次提问产生哪些 span、引用 `Citations` 从哪里来？ |
| 4. 权限 | [KnowVaultPermissions.cs](src/KnowVault.Domain.Shared/Permissions/KnowVaultPermissions.cs) → [KnowVaultIdentityDataSeedContributor.cs](src/KnowVault.Domain/Seeds/KnowVaultIdentityDataSeedContributor.cs) → [KnowledgeBaseAccessChecker.cs](src/KnowVault.Application/KnowledgeBases/KnowledgeBaseAccessChecker.cs) → 各 AppService 的 `EnsureAsync` | Admin、默认知识库、普通成员三条路径分别怎么放行？ |
| 5. 生命周期与重试 | `DocumentAppService.DeleteAsync` / `ReprocessAsync` → [IVectorStore.cs](src/KnowVault.Domain/VectorStore/IVectorStore.cs) / [IDocumentStorage.cs](src/KnowVault.Domain/Storage/IDocumentStorage.cs) → [KnowVaultIngestModule.cs](src/KnowVault.Ingest/KnowVaultIngestModule.cs) | 删除顺序为什么是 Qdrant→切片→文档→MinIO？重处理为什么不会重复切片？ |
| 6. 横切与回归 | [KnowVaultObservabilityExtensions.cs](src/KnowVault.HttpApi.Host/Observability/KnowVaultObservabilityExtensions.cs) → [KnowVaultTelemetry.cs](src/KnowVault.Domain.Shared/Telemetry/KnowVaultTelemetry.cs) → [ActivityTraceEnricher.cs](src/KnowVault.HttpApi.Host/Observability/ActivityTraceEnricher.cs) → `tests/KnowVault.IntegrationTests/` → `.github/workflows/ci.yml` | Trace 如何从 HTTP 串到 RAG/EF？集成测试怎么既绕开授权拦截器、又真实验证 ACL？ |

读法建议：

1. 先 `dotnet build KnowVault.slnx`，保证能编译，再开始读。
2. 每步只开 2–3 个文件，沿一个方法点进去，不要一次把整个项目铺开。
3. 第 2、3 步建议配合 Seq 看真实 trace，比只看代码更容易建立整体感。

## 本地验收命令

```powershell
dotnet build KnowVault.slnx
dotnet test tests/KnowVault.Tests/KnowVault.Tests.csproj
dotnet format analyzers KnowVault.slnx --no-restore --verify-no-changes --diagnostics IDE1006

# 集成测试需要 Docker；本机 MinIO 镜像拉不到时：
$env:KNOWVAULT_SKIP_MINIO='1'
$env:DOCKER_API_VERSION='1.44'
$env:DOCKER_HOST='npipe:///./pipe/dockerDesktopLinuxEngine'
dotnet test tests/KnowVault.IntegrationTests/KnowVault.IntegrationTests.csproj
```

## 两个容易踩的坑

1. **Qdrant 端点**：gRPC 是 `6334`，不是 REST 的 `6333`；Testcontainers 里要显式 `Configure<QdrantOptions>` 覆盖端点，光 `ReplaceConfiguration` 不够（EF 模块在依赖阶段已绑定旧配置）。
2. **集成测试连接串**：`AbpDbConnectionOptions` 必须在测试模块 `PreConfigureServices` 里设置，否则会报 `The ConnectionString property has not been initialized`。

## 手工验收（尚未自动化）

- Seq：提问一次，确认 `HTTP → qa.ask → rag.retrieve → llm.complete` 及 EF span 在同一 trace。
- 权限：用 `viewer` 账号上传，应 403；用 Owner 添加成员后，Editor 可上传、Viewer 只读。
- 重试：构造解析失败文档，确认 5 次后 `Status=Failed`，RabbitMQ `document-ingest_error` 有 1 条。
